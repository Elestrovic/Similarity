更新: **2026-10-24**

## 3段階のステータス

1. **合意した設計方針** — 会話で意味や方向性を決めたこと。実装済みとは限りません。
2. **未確定・検討中** — 書式・意味論・エラー条件・例外ケースなどが決まり切っていないこと。
3. **既存実装（legacy prototype）** — `lexer/`、`parser/`、`backend/`、`cbackend/` 等の**今あるコード**から確認できること。設計方針と違っていても自動的に新仕様の根拠にはなりません。

## 旧資料の整理

2026-10-24、旧資料に互いに矛盾する主張、実装状況の古い断定、すでに見直した文法・型システムが見つかったため、次を現行の仕様資料から**削除**しました。

- `docs/Language.md`
- `docs/similarity_full_spec.md`
- `docs/SIMILARITY_HANDOFF.md`
- `docs/StandardLibrary.md`
- `docs/FFI.md`
- `docs/Cell.md`
- `docs/Echo.md`
- `docs/CAI_SPEC.md`

旧資料そのものはGitの履歴から確認できます。古い書き方が新しい仕様であるという誤解を避けるため、旧仕様書を「完全版」「正式な参照先」として残してはいません。

**削除したのは文書だけです。** 旧ドキュメントが説明していた`stdlib/`、`cel/`、`echo/`、`caigen/`などの実装コードは削除していません。これらの機能をどう正式なSimilarityに位置づけるかは、今後の設計に委ねます。

**議事録は歴史的な検討記録として維持**しています。議事録に言及される`docs/Language.md`等の旧ファイル名は議論当時の参照であり、現行資料への案内ではありません。

## メンテナンス方針

- 新しい設計を加える際は「合意／検討中／実装確認済み」を明記する。
- 機能が実装されたと書く前に、対応コードまたはテストで裏付ける。
- セルフホスティングに関係する設計変更は`self-hosting.md`にも反映する。
- 未解決の詳細を推測して仕様として確定させない。
