# Similarity セルフホスティング計画

**更新:** 2026-10-24  
**状態:** 研究計画。実装済みではありません。

## 目標

**SimilarityでSimilarityのコンパイラを書く。** すべての言語機能や全OS対応が完成する前に、セルフホスティングに不可欠な能力を備えた最小処理系を作ります。

2026-10-24、GitHubの**旧試作コンパイラソースは削除済み**です。現行ツリーには新コンパイラの実装はなく、Stage 0もこれから用意します。旧ソースはGit履歴に残っています。

## 概念上の段階

```text
Similarity製コンパイラのソース
       ↓（Stage 0: 最初のブートストラップ処理系）
Stage 1: Similarity製コンパイラ
       ↓（自分自身をコンパイル）
Stage 2: 再生成されたSimilarity製コンパイラ
       ↓
動作・出力を比較して検証
```

## 最小限必要な機能

| 能力 | 用途 | 詳細 |
| --- | --- | --- |
| 整数、真偽値、文字・バイト列 | ソース中の文字と状態 | 未確定 |
| 変数、代入、型の決定 | 位置と値の管理 | 決定的推論は認める方向 |
| 算術、比較、ビット演算 | 数値と文字の判定 | 前置記法を検討 |
| 関数・引数・戻り値 | 分割した処理の連携 | `Func` 等を検討 |
| 分岐・反復／探索 | 入力解析と制御 | `If`／`Explore` 等の案 |
| データ構造 | Token、シンボル、処理状態 | 未確定 |
| メモリ管理 | バッファと可変長データ | 未確定 |
| 入出力 | ソース読込と生成物出力 | 未確定 |
| エラーと診断 | 不正入力の検出 | 未確定 |

`until`、`here`、`asfor`などの汎用構文は、必要に応じて段階的に実装してよい。**最初の処理系ですべてを完成させることを要求しない。**

## 今後の工程案

1. 小さなプログラムとエラー例で最小仕様を検証する。
2. Stage 0の方式を選定・実装する。既存Go/C方式やLexer/Parser/ASTに自動的に戻るわけではない。
3. 初期ターゲット向けにコンパイル→実行できる最小経路を確立する。
4. 必要なデータ表現、メモリ、I/Oを整える。
5. SimilarityでSimilarityコンパイラを書き、Stage 1とStage 2の振る舞いを確認する。

Linux x86-64 ELFを初期ターゲットとする案はありますが、現段階で確定した実装仕様ではありません。ABIやGCを使わない安全なメモリ管理、型推論の詳細、コンパイラ内部経路は引き続き研究します。
