# Similarity セルフホスティング計画

更新: **2026-10-24**  
**位置づけ:** 研究・開発計画。**実装済みでも期限を確約したものでもありません。**

## 目的【合意した方針】

**SimilarityでSimilarityのコンパイラを書く**ことを早期目標とする。完成した言語仕様やすべてのOS対応を待たず、コンパイラを書くために不可欠な最小機能を先に固める。

## ブートストラップ

```text
Similarity製コンパイラのソース
           ↓ Stage 0（初期実装がコンパイル）
Similarity Compiler / Stage 1
           ↓ 自分自身のソースをコンパイル
Similarity Compiler / Stage 2
           ↓ 出力と動作を比較・検証
      セルフホスティングの確認
```

最初はLinux x86-64 ELFを仮の初期ターゲットとする**提案**。後のマルチOS対応、独立ABI、標準ライブラリ構築と両立できるよう、ターゲット固有コードを設計上切り分ける。

**成功基準の候補:** Stage 1とStage 2の双方が同じ妥当な入力を受理し、期待されるプログラムを生成すること。出力バイナリのバイト列完全一致を条件にするか、再現可能ビルドやブートストラップの信頼性をどう検証するかは未決定。

## コンパイラを書くために必要な能力

| 最小機能 | なぜ要るか | 正確な文法 |
| --- | --- | --- |
| 数値・真偽値・文字列／バイト列 | ソース中の字句・数値・状態 | 未確定 |
| 変数・代入・宣言された型の参照 | 字句走査・解析状態 | 設計中 |
| 算術・比較・ビット演算 | 文字コード・長さ・分岐 | 前置記法の方向 |
| 関数・引数・戻り値 | 機能分割 | 番号付き引数を検討中 |
| 条件分岐・反復・終了 | 走査・判断・ループ | `If`、`Explore`等を検討中 |
| データ構造とコレクション | Token、シンボル表、解析情報 | 未確定 |
| メモリの確保・参照・解放 | 可変長の入力・内部状態 | 未確定 |
| ファイル・入出力 | ソース読込・成果物出力 | 未確定 |
| エラー・診断 | 不正なソースの拒否 | 未確定 |

**留意:** `until`などの便利な表現をすべて完成させないと最小コンパイラが書けない、とは限りません。また「コンパイラを作る」に必要な技術と、「言語が自分をコンパイルできる」に必要な技術を分けて優先順位を決めます。

## 取り組みの順序【提案】

1. **最小プログラムを決める:** 変数、演算、引数、条件、文字列・バイト走査などの小さなサンプルと失敗例を定義する。
2. **最小データ表現:** Token、バッファ、シンボル、エラー情報を表現できるか実際に試す。
3. **フロントエンド能力:** 合意した文法を受理し、不正構文・曖昧な型・引数番号の欠番を拒否する。
4. **機械語までの経路:** 既存バックエンドのCFG以降を実装するか、独立の最小実験経路を使うかを選定。ネイティブ成果物の起動まで確認する。
5. **Stage 0→Stage 1→Stage 2:** セルフホスティング用コンパイラをSimilarityで書き、再ビルドして挙動を比較する。
6. **その後:** 最適化、対応OSの増加、標準ライブラリ全体、新しいメモリ管理設計の検証を継続する。
